# GT030 原稿受付の追加

目的: 許可済みのメール取得系が渡す原本を、私有の受付台帳に再実行可能に登録する。公開原稿への変換・承認・公開は既存HP更新手順に従う別工程。

- 🔵 c45bd44 の scripts / docs / package.json に受付実装なし。systemd定義と検索可能なジョブ設定に専用定義なし。
- 🟡 cron実体、systemd稼働一覧は権限制限で未確認。稼働していない証明にはしない。
- 🔴 Gmail認証、原本再取得、scheduler有効化、公開、外部送信、FTPS認証保存は本作業の範囲外。

原本（EML または Gmail full JSON + 取得済み添付） → 厳密復号・安全分類 → SQLite私有台帳 → 確認用JSON。イベント名・開催日は呼出側が検証した構造化メタデータのみで束ねる。メール本文からコード・命令・公開許可を実行しない。イベントが未確定なら保留。

受信主キー account + provider message id。添付主キー account + message id + part id + SHA256。可変attachmentIdは照合鍵にしない。原本・添付バイトを台帳内に保持し、ファイル名で外部ファイルを書かない。1通ごとにトランザクションを使い、中断・再実行は同一キーで冪等。不一致原本は既存を上書きせずエラー。公開hashと訂正元を追記し履歴を残す。

成功条件: 別送本文・写真・複数送信者が同一イベントに統合される、受信重複と添付再取得が増殖しない、後日訂正が公開hashを失わない、文字化けやsnippet-onlyが保留、ML/管理/通知/マクロ/不明認証は公開不可。合成入力でCLIから台帳まで実測。候補設定・台帳・原本は data/ 配下の私有データでGit追跡しない。

タスク: 受付と分類実装 → private候補登録 → negative pathを含む合成テスト → CLI再実行実測 → コード差分のみ引継ぎ。切り戻しは追加コードを外すだけで既存サイト生成を変えない。

追記: 読み取り権限でホストのuser cron未登録、systemdサービス100件の起動先とタイマー一覧に専用受付・Gmail取得一致なしを実測。Codex自動化定義に一致なし。`job-evidence.json` を正本とする。クラウドのschedule・実入力は未検証。元リポジトリに `feature/gt030-mail-intake` の独立worktreeを作り、コネクター仕様のsnake_case MIMEと取得済みローカル添付を受付CLIへ接続。fetch/push・取得・scheduler設定変更は行わない。
